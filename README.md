# Система учёта заявок на ремонт техники

Десктопное приложение для автоматизации приёма и обработки заявок на ремонт бытовой и цифровой техники. Создано на Java с современным графическим интерфейсом JavaFX. Позволяет клиентам оставлять заявки на ремонт, а мастерам — отслеживать статус работ, вести технические заметки и формировать историю обращений.

---

## О проекте

**Почему был создан этот продукт?**

Repair Management System появилась как практическая реализация цифровой системы учёта для сервисного центра по ремонту техники. Проект объединяет потребности клиентов в быстром оформлении заявок и отслеживании статуса ремонта с инструментами мастера для управления очередью, диагностики и контроля выполнения работ. Разработка велась как комплексный пример полноценного десктопного приложения с локальной базой данных, ролевой моделью доступа и адаптивным интерфейсом.

**Какую проблему он решает?**

Приложение предоставляет единую цифровую среду для организации ремонтных процессов без зависимости от интернета и облачных сервисов. Оно автоматизирует рутинные операции: приём заявок, распределение по статусам, ведение технических заметок, расчёт стоимости и формирование истории, заменяя бумажные журналы и разрозненные записи структурированной системой.

**В чём его ключевые преимущества?**

- **Полная локальность и автономность** — Все данные хранятся в локальной базе SQLite на вашем компьютере, не требуется интернет и сервер
- **Ролевая система** — Разграничение прав доступа для клиентов и мастеров из коробки
- **Комплексное управление заявками** — Создание, статусы, заметки, стоимость и поиск в одном приложении
- **Цветовая индикация статусов** — Визуальное отображение стадии ремонта (новая, в ремонте, готова, выдана)
- **Готовое рабочее решение** — Полнофункциональное приложение с типовыми сценариями сервисного центра «из коробки»
- **Простая установка** — Не требуется сборщик Maven, достаточно Java 17+ и JavaFX 21

## Технологии

Для работы приложения требуется:

- **Java Development Kit (JDK) 17 или выше** — язык программирования и runtime
- **JavaFX SDK 21** — графический интерфейс (FXML, CSS)
- **SQLite JDBC Driver 3.45+** — встроенная база данных
- **IntelliJ IDEA Community Edition** — рекомендуемая IDE для разработки и запуска

**Архитектура проекта:**

| Компонент | Технология |
|-----------|------------|
| Язык программирования | Java 17 с JavaFX 21 |
| База данных | SQLite 3 (файл `repair_system.db`) |
| Архитектура | MVC с чётким разделением: модель, DAO, контроллеры, представление |
| Графический интерфейс | JavaFX с FXML-разметкой и CSS-стилизацией |
| Безопасность | Ролевая модель доступа (клиент / мастер), локальное хранение данных |
| Дополнительные компоненты | Поиск по заявкам, цветовая индикация статусов, подсчёт количества |

## Быстрая установка и запуск

Вы можете запустить приложение за несколько минут:

### 1. Установите необходимое ПО

- Установите JDK 17 по ссылке: [oracle.com/java/technologies/downloads](https://oracle.com/java/technologies/downloads)
- Скачайте JavaFX SDK 21 по ссылке: [gluonhq.com/products/javafx](https://gluonhq.com/products/javafx)
- Скачайте SQLite JDBC Driver: [github.com/xerial/sqlite-jdbc/releases](https://github.com/xerial/sqlite-jdbc/releases)
- Установите IntelliJ IDEA: [jetbrains.com/idea/download](https://jetbrains.com/idea/download)

### 2. Настройте проект в IntelliJ IDEA

1. Создайте новый Java-проект **без Maven**
2. Создайте папку `lib` и поместите туда `sqlite-jdbc-3.45.1.0.jar`
3. Распакуйте JavaFX SDK в удобное место (например, `C:\javafx21`)
4. В `Project Structure → Libraries` добавьте папку `lib` из JavaFX SDK и jar SQLite
5. В `Run → Edit Configurations` укажите VM Options:
   6. Убедитесь, что `Working directory = $ProjectFileDir$`

### 3. Запустите приложение

Нажмите зелёную кнопку **Run** (`Shift+F10`) в IntelliJ IDEA. При первом запуске база данных создастся автоматически, будет добавлена учётная запись мастера (логин: `master`, пароль: `master`).

## Возможности

Repair Management System предоставляет полный цикл управления заявками на ремонт:

- **Система пользователей** — Регистрация и авторизация с ролями `CLIENT` и `MASTER`, изоляция данных
- **Управление заявками** — Создание карточек с типом устройства, моделью, серийным номером и описанием поломки
- **Статусы ремонта** — Автоматический переход по цепочке (новая → диагностика → в ремонте → ожидание запчастей → готова → выдана)
- **Технические заметки** — Ведение записей о выполненных работах и использованных запчастях
- **Финансовый учёт** — Указание итоговой стоимости ремонта для каждой заявки
- **Поиск и фильтрация** — Быстрый поиск по ФИО клиента, модели устройства или серийному номеру
- **Цветовая индикация** — Визуальное отображение статуса заявки в таблице (синий, жёлтый, зелёный, красный)
- **Удаление заявок** — Возможность удалить выполненную или отменённую заявку из системы

## Использование

### Начало работы

При первом запуске авторизуйтесь как мастер (логин: `master`, пароль: `master`) или зарегистрируйтесь как новый клиент. После входа откроется рабочее пространство с боковым меню и списком заявок.

### Основные функции (боковое меню)

| Раздел | Описание |
|--------|----------|
| **Новая заявка** | Форма создания заявки на ремонт (доступно клиенту и мастеру) |
| **Все заявки** | Таблица заявок с цветовой индикацией статуса, поиском и кнопкой удаления |
| **Детали заявки** | Открывается по двойному клику: две вкладки — Информация и Ремонт (редактирование только для мастера) |

### Работа с данными

- Двойной клик по строке заявки открывает детальную карточку с полной информацией
- Клиент видит **только свои** заявки, мастер — **все** заявки в системе
- Мастер может изменять статус, добавлять заметки и указывать стоимость ремонта
- Все изменения сохраняются автоматически в базу данных SQLite
- Поиск работает по ФИО клиента, модели устройства или серийному номеру

## Разработка и тестирование

Проект построен на архитектуре **MVC** с чётким разделением:

- **Модели:** `User`, `RepairRequest`, `Role`, `Status`
- **DAO-слой:** `UserDAO`, `RepairRequestDAO` — прямая работа с SQLite через JDBC
- **Контроллеры:** `LoginController`, `MainController`, `CreateRequestController`, `RequestListController`, `RequestDetailController`
- **Представление:** FXML-файлы (`login.fxml`, `main.fxml`, `create_request.fxml`, `request_list.fxml`, `request_detail.fxml`) + CSS-стили
- **Утилиты:** `SessionManager` — хранение текущего пользователя, `Database` — инициализация и подключение к БД

### Тестирование

Проведено комплексное тестирование, охватывающее основные сценарии использования:

| Тест-кейс | Сценарий | Охватываемый функционал |
|-----------|----------|------------------------|
| T1 | Полная регистрация и вход клиента | Аутентификация, создание профиля, ролевая модель |
| T2 | Вход мастера и просмотр всех заявок | Авторизация, загрузка интерфейса, разграничение доступа |
| T3 | Создание заявки клиентом | Форма создания, валидация полей, сохранение в БД |
| T4 | Изменение статуса и заметок мастером | Редактирование заявки, статусы, технические заметки |
| T5 | Поиск заявок по разным критериям | Поиск по ФИО, модели, серийному номеру |
| T6 | Удаление заявки и обновление списка | Удаление из БД, пересчёт количества |
| T7 | Проверка прав клиента (только чтение) | Блокировка редактирования для клиента |
| T8 | Интеграционные сценарии | Переходы между окнами, сохранение данных при закрытии |

Интеграционное тестирование проводилось на основе графа переходов между окнами приложения, обеспечивая покрытие всех ключевых пользовательских сценариев.
